# stellar-diver: handoff

A decompiler for Soroban (Stellar) smart contracts: wasm -> typed LLVM IR ->
rustc's own MIR -> Rust, and, as far as the analysis carries, back to the
soroban-sdk source the contract was compiled from. This file is what the next
agent needs to pick it up. `samples/README.md` is the long-form design
document; this is the map, the state, and the plan.

## The one-paragraph state

The lowering is sound on everything we have: 68 binaries (24 mainnet
contracts, 43 SDK fixtures, the sample) lift to verified LLVM IR with
4 bottoms left in total (two `memory.size`/`memory.grow` each), every one
builds as MIR inside rustc and passes borrowck, and every emitted Rust file
type-checks under stable rustc. The Val-level Rust is faithful and readable
for storage-centric code: keys, struct and union values, symbols and strings
appear as the source wrote them, derives are named, SDK functions are named
by fingerprint. The source-level output (`--contract`) compiles as a soroban
contract for every binary but reconstructs only 55 of 712 export bodies
whole; the rest are `todo!()`s naming the blocker. The next work is there:
the contract's own helpers, and i128/u128 arithmetic.

## Invariants (do not trade these away)

1. **Typed IR.** `%Val` is a distinct LLVM struct type, never an `i64`. A
   Val/i64 confusion is a verifier error, and `lower_module` runs
   `m.verify()`. Hand-written text IR cannot check this; that is why inkwell.
2. **A real CFG.** Every `br_table` arm, every label, is a basic block. No
   arm is dropped, no jump table becomes a lookup that can fall off the end.
3. **Bottom is not a value.** Anything the model cannot carry is a call to
   `@diver.unknown` / `@diver.unknown.i64`, never a plausible literal.
   `DIVER_WHY_UNKNOWN=1` prints why each one was made. The corpus is at 4.
4. **The output is checked by the real compilers.** LLVM verifies the IR,
   rustc borrow-checks and validates the MIR (`-Zvalidate-mir`), stable
   rustc type-checks the Rust, cargo builds the reconstructed contract
   against soroban-sdk. Nothing is "probably fine".
5. **Never claim what is not known.** Several shapes are `Union::{A, B}` or
   `A | B`, never one of them. A payload the caller did not write is `_`. An
   export that cannot be said at the source level is a `todo!()` with the
   reason.

```
  src/lower.rs                 one wasm function -> one LLVM function: operand stack, labels, frames, operators

  src/host.rs                  the host ABI table (generated by build.rs from env.json)
  src/val.rs                   Val constants decoded
  src/fingerprints.rs          SDK fingerprints: hashing, tables, names
  src/optimize.rs              LLVM's passes and our folds
  src/decode.rs                names and metadata after optimisation
  src/spec.rs                  contractspecv0 as lines
  src/tests.rs                 unit tests (14)
  build.rs, env.json           host function table, from soroban-env's env.json
  shell.nix                    LLVM 18 (llvm-sys prefix, libffi); use nix-shell for both crates
  rust-toolchain.toml          stable 1.97.1 + wasm targets, for building sample contracts
  mir/                         crate 2: LLVM IR -> MIR inside rustc -> Rust / contract (binary `stellar-diver-mir`)
    rust-toolchain.toml        nightly-2026-05-01 with rustc-dev (rustc_private)
    src/main.rs                driver: rustc callbacks, build_mir hook, CLI
    src/header.rs              the stub crate's text: prelude, header, stubs
    src/mir.rs                 the MIR builder (LLVM instructions -> rustc_middle::mir)
    src/infer.rs               parameter/return type inference (Ptr/Val/Int/Storage)
    src/rs/mod.rs              Inter (the summaries), summaries(), emit(), emit_contract(), Fn_
    src/rs/spec.rs             the spec as the emitter sees it
    src/rs/text.rs             text-level helpers: constants, shapes, templates, source-level rewrites
    src/rs/frames.rs           Val arrays, literal arrays, words read through pointer parameters
    src/rs/values.rs           locals, places, constants, rvalues as Rust
    src/rs/calls.rs            statements and calls: folding, shapes, summaries, the storage schema
    src/rs/sdk.rs              the source level: an export as soroban-sdk code
    src/rs/structure.rs        structured control flow, or a state machine
    tests/e2e.rs               end to end on the checked-in .inline.ll goldens; builds the contract
  samples/                     source project, vendored fixtures, goldens, README.md (design doc)
    build.sh                   rebuilds the samples and regenerates every golden (the regression gate)
    corpus.sh                  the corpus gate; prints the numbers tracked below
    contract/                  Cargo.toml for the reconstructed contract (src/lib.rs is generated, ignored)
  fingerprints/                SDK fingerprint tables, the reference contract, gen.sh
```

Untracked scratch at the top level (`*.ll`, `*.bc`, `sos/`) is ignored; leave
it alone or delete it.

## Build, test, measure

```sh
nix-shell                                        # LLVM 18 for inkwell; both crates build inside it
cargo build --release                            # stellar-diver
cargo test --release                             # 14 tests, including the fingerprint one
(cd mir && cargo build --release && cargo test --release)   # 2 e2e tests, ~2 s
./samples/build.sh                               # rebuild samples, regenerate goldens, build the contract
git diff samples/                                # a codegen change is a diff here, never noise
./samples/corpus.sh <soroban-ret checkout>       # the numbers in "Where it stands"
```

Always run `stellar-diver-mir` through `cargo run`: the binary alone cannot find
`librustc_driver`. The nightly must have `rustc-dev`; rustup installs it from
`mir/rust-toolchain.toml`.

The corpus is not vendored. Clone https://github.com/Inferara/soroban-ret and
use `benchmark-data/mainnet/*.wasm` (24 real contracts, 568 KB) and
`tests/fixtures/*.wasm` (43 SDK fixtures). During this work it lived in
another session's scratch directory under `/tmp`; do not rely on that path.
`unknown-oracle-CAWGFKEL` (Allbridge's gas oracle, by its errors) and
`arb-bot-contract-CCBVCCNP` are the closed-source ones.

Toolchains needed beyond nix-shell: rustup `stable` with `wasm32v1-none`
(sample and reconstructed-contract builds), `1.95.0` if you regenerate the
exact-toolchain fingerprint tables, `wasm-tools` for inspecting wasm,
`uv run python3` if you script (the machine blocks bare `python`).
soroban-sdk 25.3.2 and 26.1.1 are in the cargo cache, so the sample and the
contract build offline; other SDK versions need the network once.

## The pipeline, stage by stage

### 1. wasm -> LLVM (`src/module.rs`, `src/lower.rs`)

`lower_module(wasm, mode)` parses every section, then lowers each function
with `lower()`: an abstract operand stack of `SV` values (`Const`, `Reg`,
`Frame(off)`, `Unknown`), wasm locals as allocas, labels as basic blocks with
a result slot per typed block (mem2reg makes the phis). The value model is
i64-wide; i32 operations narrow their operands and widen their result
(`binop(op, w32)`, `cmp(p, w32)`), so wrapped values never leak high bits.

Things it recovers: the shadow-stack frame (`global.get 0; i32.const N;
i32.sub|add -N; local.tee; global.set 0`) as an `alloca`, with `SV::Frame`
addresses that stay symbolic through `add`/`sub` by a constant and through
once-assigned locals (`frame_alias`); pushes the body makes part-way
(`global.get 0; i32.const k; i32.sub; global.set 0` around one call, rustc
1.86's derives do this) as `bias` bytes below that frame, the stack pointer
tracked as a frame offset (`sp`) so `global.get 0` is an address; linear memory (`Mem`: data segments,
zero past a segment's end, `written` if any store hits a segment at a
constant address); the function table for `call_indirect` (`table_global`).

Modes: default lowers exports only; `--all` every function; `--inline` every
function with helpers internal, then LLVM `default<O1>` plus a loop of
`sroa,instcombine,gvn,dse,simplifycfg,adce,...,loop-unroll` under the
**wasm32 target data layout** (32-bit pointers: this is what lets the frame
folds see through i32 arithmetic), plus our own folds
(`fold_frame_pointers`: `inttoptr(ptrtoint(frame)+k)` -> gep;
`fold_data_loads`: constant loads from rodata). `--inline` is what
stellar-diver-mir consumes.

After optimisation `rename_decoded` names values after what they are
(`Symbol("Pair")`, `has_contract_data`, `StorageType::Persistent`) and
records metadata the next stage reads:

| metadata / attribute | meaning |
|---|---|
| `soroban.spec` | one line per `contractspecv0` entry: `struct N { a: T }`, `union N { A, B(T) }`, `enum N { A = 0 }`, `error N { X = 1 }`, `fn name(p: T) -> R`, `event N` |
| `soroban.keys` | `pos k1 k2 ..`: map key names (and union case names for `symbol_index_in_linear_memory`) by rodata position |
| `soroban.strings` | `pos text`: symbol/string texts by rodata position |
| `soroban.rodata` | `base hex`: the read-only segments, when nothing writes them |
| fn attr `wasm.type` | the wasm value type of each param/result (`i32`/`i64`) |
| fn attrs `spec.name`, `spec.type`, `spec.sig` | an export's declared parameter names/types and signature line |
| fn attr `sdk.name` | the demangled SDK path a fingerprint matched |
| fn attr `soroban.import` | the host import a declaration stands for |

The IR's first line says what the fingerprints did:
`; sdk 22.0.7 rustc 1.81.0; fingerprints 25.3.2.txt (nearest): 9 of 91 helpers named, 4 by shape`.

Other modes: `--sdk` prints the SDK and rustc versions from `contractmetav0`;
`--fingerprints` prints a fingerprint table for a wasm that kept its symbol
names (used by `fingerprints/gen.sh`).

### 2. Types (`mir/src/infer.rs`)

Candidates from `wasm.type` (i32 -> Ptr or Int; i64 -> Val, Storage or Int),
evidence from uses (loads/stores -> Ptr, `from_payload` -> Val, host argument
positions, links across calls, tag checks), solved to a fixpoint. Exports keep
the Val ABI; helpers get `u64`, `*mut u8`, `Val` or `StorageType`.

### 3. MIR inside rustc (`mir/src/main.rs`, `mir.rs`)

The driver writes a stub crate (prelude + `extern "C"` host functions + one
empty fn per lifted function), runs `rustc_driver` on it with
`override_queries` replacing `build_mir` by ours, and `mir.rs` builds
`rustc_middle::mir::Body` from the LLVM function: allocas as `[u64; N]`
arrays, frame slots as `ConstantIndex`, `Val(x)` aggregates, casts with
provenance ops, `transmute` calls for StorageType. rustc then borrow-checks,
validates, and optimises it (`-Zmir-opt-level=3`); `after_analysis` collects
`optimized_mir` per function. Without `--rust` it dumps the MIR (the `.mir`
goldens).

Known drop: an indirect call (a GEP into `__table`) is not built; the
function is skipped with `stellar-diver-mir: fN: gep shape ...` on stderr (7 in the
corpus, all in `soroban-domains`).

### 4. Rust from MIR (`mir/src/rs/`, `emit`)

Structured emission (Ramsey-style: dominators, RPO, merges as labelled
blocks, loops, `match` for `SwitchInt`), a state machine when irreducible.
Then the layers that make it read like the contract:

- **Prelude** (`mir/src/header.rs` `PRELUDE`): `Val` newtype with `sym`, `u32`,
  `error`, `small`; `StorageType`; `Tag` consts; `pos()`, `str_at()`; and,
  per import present, the SDK constructors on `Val`: `Val::symbol`,
  `Val::string`, `Val::vec`, `Val::map`.
- **Shapes**: every Val local carries what it is (`DataKey::Pair(PairKey { a,
  b })`, `Symbol("x") /* U::Case */`) with the switch arms it was made under
  (`Cond`). `key_shape` renders a storage key in the contract's terms.
- **Summaries** (`Inter`), iterated to a fixpoint by `summaries()`:
  `ret_shapes` (a helper's returns, params as placeholders, words read through
  pointer params as `a0@8`, plus the arms), `param_accesses` (a helper keyed by
  a parameter reports at its callers, `via fN`), `unpacks` (types a fn unpacks
  from the host), `param_writes` (which pointer params a fn writes through and
  how far), `fails` (panic wrappers by their error), `diverges`, `renames`
  (derive names), `text_helpers` (`Symbol::new`-like helpers take `&str`),
  `encoders` (the SDK's `SymbolSmall::try_from_bytes`, recognised by its
  constants: six bits a character under tag 14).
- **Frame words** (`words_at`): what a frame slot holds at a statement, from
  the stores on every path into its block, merged where paths join -- one
  value where they agree, else one per path under that path's arms (a
  `Vec<(Vec<Cond>, shape, const)>`); a writing callee clobbers, the encoder
  writes its symbol, a loop forgets what its body touches. A local loaded
  from a slot takes those values, so a derive's shared tail (`(sym,).into_val`
  after a `match`) returns one shape per arm.
- **Call sites**: `frame_words` reads what the caller wrote into a frame it
  passes, less what a writing callee may have clobbered, to select the
  callee's arm and fill its payload:
  `lc = BackstopDataKey_into_val(_59); // BackstopDataKey::PoolBalance(a1)`.
  A `Cond` is on a word read through a pointer parameter (`a0@8`) or on an
  integer parameter itself (`a0`: an enum's discriminant passed split from
  its payload), which a constant argument selects:
  `DataKey_into_val(3u64, arg_payload); // DataKey::Escrow(account)`.
- **Derive recognition**: every return a case of one union / one struct's
  map -> `T_into_val`; unpacking one type's fields or cases -> `T_try_from_val`;
  functions that touch storage are getters/setters, not derives.
- **The storage schema** in the header: every put/get/has/del/extend_ttl
  call, by durability, key, and uses.
- **Field names**: a payload local landing under map key `pool` is named
  `pool`.

### 5. Contract from MIR (`mir/src/rs/sdk.rs`, `emit_contract`, `--contract`)

Types from the spec lines (`type_item`), `#[contract] pub struct Contract`,
one `pub fn` per export with the spec signature and `env: Env` first, bodies
translated statement by statement in "SDK mode" (`sdk: true` on `Fn_`):
`sdk_stmt`, `sdk_call`, `sdk_switch`, `sdk_operand`, `sdk_value`, `wrap_ret`.
Storage host calls become `env.storage().persistent().has(&key)` with the key
as its shape; symbols `symbol_short!`/`Symbol::new`; error and union cases
their paths; returns wrapped per the declared type; enum-parameter switches
`match`; guards (tag checks whose other arms trap) elided; panic wrappers
`panic_with_error!`. Anything else makes the export a `todo!()` with the
reason. `samples/three_bugs.contract.rs` is the sample's own source up to
`.clone()`s and a `match` for an `if` chain, and `build.sh`/the e2e test
compile it against soroban-sdk for `wasm32v1-none`.

### SDK fingerprints (`fingerprints/`)

`gen.sh <sdk-version> [toolchain]` builds `fingerprints/ref` (a contract that
uses the SDK broadly) at that exact version with symbol names kept, lifts it,
and writes `<version>.txt` or `<version>+rustc<ver>.txt`: exact fingerprint,
shape fingerprint, demangled path per SDK/core/compiler-builtins function.
Tables are searched in `$DIVER_FINGERPRINTS`, else
`~/.cache/stellar-diver/fingerprints` and the repo's `fingerprints/`; the
nearest SDK version wins, toolchain match preferred. Exact fingerprints match
only the same build; the shape one (signature + host calls + constants +
counts) survives wasm-opt and register allocation and is trusted only when it
names exactly one function. Coverage is bounded by what the reference leaves
out of line: 292 of 1994 corpus helpers today. Widen `fingerprints/ref/src/lib.rs`
to widen it.

## What to do next, in payoff order

1. **Helpers as functions in the contract.** Emit non-export lifted functions
   as free `fn`s with types inferred from their spec-typed callers (a
   parameter that receives `new_admin: Address` is an `Address`; a return
   that flows to an export's `-> u128` is a `u128`), bodies through the same
   SDK mode. Storage getters/setters are the bulk. Without this most mainnet
   exports stay `todo!()`.
2. **Numeric decodes as the parameter they decode.** In an export,
   `obj_to_i128_lo64(a)`/`hi64(a)` plus the `I128Small` arm is the parameter
   `a: i128`; `__multi3` on two known pairs is `a * b` (with overflow-checks
   semantics), likewise `__udivti3` etc. Track a "wide value" as a (lo, hi)
   pair of locals with a symbolic source. This unlocks every DeFi contract.
3. **Typed storage reads.** `get_contract_data` followed by
   `T_try_from_val(out, val)` is `let x: T = env.storage()...get(&key).unwrap()`,
   and later frame reads are `x.field` (the derive's field order is the spec's,
   sorted).
4. **Indirect calls in MIR** (`mir.rs`): represent `__table` as a static of fn
   pointers and the call as a call through an element, or at least keep the
   function with the call as an opaque extern.
5. **Frame words across clobbers**: 73 derive calls still see all cases,
   mostly a getter passing its own integer parameter on (`f56(fp, 75, .., 2)`
   -> `DataKey_into_val(a3, 0)`: the getter's callers know the case, the
   getter does not -- item 1 or 3 resolves it), some a loop copying through
   a moving pointer into the same frame (`param_writes` extent unknown; bound
   the copy by its length argument when it is a known memcpy).
6. **Fingerprint coverage**: widen `fingerprints/ref` (Vec/Map/Bytes/String
   ops, more conversions, several call sites each) and generate tables for
   the corpus's toolchains (sdk 20.x/rustc 1.75-1.78, 22.0.7/1.81).
7. **Value shapes in `put(..)` rows** still show the writer's locals
   (`Val(ld6)`); the round trip (build the reconstructed contract, lift it
   again, diff the storage schema) is the natural equivalence check once more
   exports reconstruct.

## Heuristics to know about (each marked `diver:` in the code)

- The value model is i64-wide; i32 ops narrow/widen. wasm traps on division
  by zero, LLVM's `udiv`/`sdiv` are undefined on it.
- A callee handed a pointer into a frame is assumed to write from that offset
  on (the host's unpacks: exactly `len` Vals); writing below a pointer it was
  given is not Rust. A lifted callee's own writes are summarised, unbounded
  when a write goes through a moving pointer.
- Frame words at a join: a value reached under several sets of arms keeps
  the arms they share; an irreducible cycle is cut where the walk meets it;
  a loop's body forgets, never reads. Shadow-stack pushes inside a body are
  taken as sequential, not nested.
- The small-symbol encoder is recognised by three parameters and the
  constants 6 and 14 in its body, not checked to write through the first. A
  switch on a narrowing cast of an integer parameter compares the caller's
  whole constant.
- `writes_data` distrusts *all* rodata if any store hits a data segment at a
  constant address (one corpus binary, `contract`).
- A storage read with one use is inlined at its use in the contract output; a
  write between them would reorder it (not seen).
- The shape fingerprint can in principle confuse two different SDK functions
  with the same host calls, constants and counts; it is used only when unique.
- Bodies that are a single trap match several core panics; they are named
  `panic`.
- `sdk_ident` keeps `Type_method`; blanket impls (`<U as IntoVal>`) drop the
  type; tuples are `Tuple`.

## Conventions this repo was built under

- Lazy by design: YAGNI, reuse what exists, shortest working diff, one check
  per non-trivial piece of logic, and a `diver:` comment on every real corner
  cut, naming the ceiling and the upgrade path. No speculative abstractions.
- Goldens are the regression gate: after any codegen change run
  `./samples/build.sh` and read `git diff samples/`.
- Commit messages explain the why in prose (see `git log`); end with
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Commit with
  `--no-gpg-sign` from an agent session (pinentry is unreachable there).
- Never `rm -f $VAR/*`-style commands in scripts; use fresh `mktemp -d` dirs.
- Production only: nothing here targets debug builds of contracts.
- Use `inkwell`, not text IR; the verifier is the point.

## Debugging aids

- `DIVER_WHY_UNKNOWN=1 stellar-diver x.wasm --all` prints why each bottom
  was made (operator name, "underflow", "local", ...).
- `stellar-diver x.wasm --all` shows every function; `--inline` what
  stellar-diver-mir sees; the `; ...` header line shows the SDK/fingerprint status.
- `stellar-diver-mir x.inline.ll` (no flag) dumps rustc's optimised MIR; `--rust`
  the Val-level Rust with the schema; `--contract` the source level.
- `wasm-tools print x.wasm` for the wasm text; the function index in `fN`
  names is the wasm function index (imports included).
- A `.inline.ll` from `samples/` or the corpus run dir can be handed to
  stellar-diver-mir directly; that is how the e2e tests run without LLVM.
